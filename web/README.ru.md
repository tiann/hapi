# hapi-web

React Mini App / PWA для наблюдения за сессиями hapi и управления ими.

## Что он делает

- Список сессий со статусом, ожидающими одобрениями, todo и сводками.
- Представление чата с потоковыми обновлениями и отправкой сообщений.
- Сценарии одобрения и отклонения разрешений.
- Варианты Codex `request_user_input` учитывают `isOther`: **None of the above**
  фокусирует необязательные примечания, поддерживает пустые примечания и сохраняет каноническое
  проводное значение во всех языках. Записанные прочие ответы и примечания остаются видимыми
  в живых и исторических карточках; формы Pi/MCP без этого флага не меняются.
- Выбор режима разрешений и модели.
- Список машин и удалённый запуск сессий.
- Просмотр файлов и представления статуса/диффа git.
- Приглашение установки PWA и баннер офлайна.
- Необязательный счётчик непрочитанных сессий на панели задач Windows при установке как PWA Edge/Chrome (переключается в настройках отображения; по умолчанию выключен).

## Поведение во время работы

- При открытии внутри Telegram аутентификация использует init data Telegram WebApp.
- При открытии в обычном браузере можно войти через `CLI_API_TOKEN:<namespace>` (или `CLI_API_TOKEN` для пространства имён по умолчанию).
- Экран входа включает выбор хаба в правом верхнем углу; если не задан, приложение использует тот же origin, с которого загружено.
- Живые обновления приходят от хаба через SSE.
- Подсказки `@` по сессиям требуют содержимого разговора, включая разговоры без заголовка. Имена и метки каталогов влияют на отображение/поиск, но не на право на участие; пустые заглушки остаются исключёнными.

## Маршруты

Определения маршрутов см. в `src/router.tsx`.

- `/` — перенаправление на /sessions.
- `/sessions` — список сессий.
- `/sessions/$sessionId` — интерфейс чата.
- `/sessions/new` — создание новой сессии.
- `/sessions/$sessionId/files` — просмотр файлов со статусом git.
- `/sessions/$sessionId/file` — просмотрщик файлов с поддержкой диффа.
- `/sessions/$sessionId/terminal` — интерфейс терминала.
- `/browse` — просмотр рабочего пространства, включается настроенными корнями рабочего пространства раннера.
- `/share` — точка входа Share-target (POST Web Share Target → `?id=`, либо нативный `/share#url=&text=&title=`).
- `/settings` — хаб категорий настроек (мобильный) и адаптивная оболочка master-detail.
- `/settings/general` — языковые предпочтения.
- `/settings/display` — внешний вид, типографика, цвета и предпочтения списка сессий.
- `/settings/chat` — поле ввода сообщений, карточка инструментов и цвета разговора.
- `/settings/voice` — повседневные предпочтения голосового ассистента.
- `/settings/voice/voices` — полноэкранный выбор голоса.
- `/settings/voice/advanced` — персона голоса, настройка и диагностика.
- `/settings/machines` — управление машинами и статус раннера.
- `/settings/storage` — размеры хранилища SQLite для владельца хаба.
- `/settings/usage` — панель использования токенов с учётом кеша для владельца хаба.
- `/settings/about` — ссылки приложения и информация о версии.

## Возможности

### Список сессий (`src/components/SessionList.tsx`)

- Индикатор активного/неактивного статуса.
- Заголовок сессии из имени, сводки или пути.
- Отображение прогресса todo.
- Число ожидающих запросов разрешений.
- Имя агента и отображение модели.

### Интерфейс чата (`src/components/SessionChat.tsx`)

- Обсуждение сообщений с бесконечной прокруткой.
- Поле ввода для отправки сообщений.
- Выбор режима разрешений и модели для поддерживаемых агентов.
  Cursor Auto использует CLI Auto для новых/возобновлённых сессий, настроенных на Auto. Когда ACP не объявляет буквальный вариант Auto, пикер сессии предупреждает, что возврат от конкретной модели требует перезапуска; HAPI не перезапускает активную сессию автоматически.
- Управление прерыванием и передачей сессии.
- Codex **Continue planning** локально скрывает меню действий текущего предложения
  и фокусирует поле ввода, не отправляя сообщение и не заменяя его черновик.
  Документ плана остаётся читаемым; переиспользуемые карточки остаются закрытыми, а новые
  предложения получают свежие меню действий.
- Отображение размера контекста.
- Заметки на сессию (`src/components/AssistantChat/ScratchlistPanel.tsx`)
  - Панель-верстак для удерживаемых заметок/черновиков; **отличается от очереди**.
  - Добавление/удаление/переупорядочивание записей; перенос в поле ввода (копия) или очередь (отправка).
  - Записи и вложения сохраняются на хабе и синхронизируются между устройствами.
  - Переупорядочивание влияет только на текущее представление и сбрасывается при обновлении записей.
  - Горячая клавиша: Ctrl/Cmd+Shift+S для фокуса поля добавления.

### Просмотр файлов (`src/routes/sessions/files.tsx`)

- Представление статуса git (файлы в индексе/вне индекса).
- Поиск файлов через ripgrep.
- Переход к просмотрщику файлов.

### Просмотрщик файлов (`src/routes/sessions/file.tsx`)

- Отображение содержимого файла с подсветкой синтаксиса.
- Представление диффа в индексе/вне индекса.

### Терминал (`src/routes/sessions/terminal.tsx`)

- Удалённый терминал через xterm.js
- Реальное время через Socket.IO `/terminal`
- Обработка изменения размера

### Голосовой ассистент

- Бэкенды ElevenLabs (@elevenlabs/react), Gemini Live и Qwen Realtime
- Голосовое управление в реальном времени
- Стандартная и realtime-диктовка в поле ввода с выбором возможностей провайдера

### Новая сессия (`src/components/NewSession/`)

Модульное создание сессий:

- Выбор машины
- Ввод каталога с недавними путями
- Выбор типа агента
- Выбор модели
- Управление разрешениями, усилием и совместной работой для каждого агента, когда поддерживается

### First-User-Experience (FUE)

Для новой необязательной функции, чья доступность иначе была бы трудно
обнаружима, рассмотрите существующий примитив FUE, а не постоянный блок интерфейса.
Необязательно, не требование для каждой функции и не повод расширять исправление бага.

- `src/lib/use-fue.ts`: `useFue(featureId)` возвращает `{ status, engage, dismiss }`; подтверждение изолируется для каждой функции в ключах localStorage `hapi.fue.v1.<featureId>`.
- `src/components/Fue.tsx`: `FueDot` отмечает доступность; `FueCallout` объясняет её, пока `status === 'engaging'`.
- Закрытие требует утвердительного действия пользователя («Got it»), никогда автоматического таймаута.
- Точка FUE и специфичные для функции бейджи/счётчики взаимно исключают друг друга; онбординг побеждает до подтверждения.
- Включайте по функции; пропускайте обёртку, если вышестоящий компонент уже предоставляет онбординг.
- Рабочий пример: `ScratchlistToggleButton` в `src/components/AssistantChat/ComposerButtons.tsx`. Используйте исходник, а не поддерживаемую здесь копию примера.

## Аутентификация

См. `src/hooks/useAuth.ts` и `src/hooks/useAuthSource.ts`.

- Telegram Mini App: использует initData из WebApp SDK.
- Браузер: использует CLI_API_TOKEN из приглашения входа.
- JWT-токены с автообновлением.

## Получение данных

Хуки запросов см. в `src/hooks/queries/`, мутации — в `src/hooks/mutations/`.

- Сессии, сообщения, машины через TanStack Query.
- Статус git и файловые операции.
- Оптимистичные обновления при отправке сообщений.

## Обновления в реальном времени

См. `src/hooks/useSSE.ts`.

- SSE-соединение с `/api/events`.
- События обновления сессий/сообщений/машин.
- Автоматическая инвалидация кеша по событиям.

## Разработка

Из корня репозитория:

```bash
bun install
bun run dev:web
```


Если тестируете в Telegram, задайте:

- `HAPI_PUBLIC_URL` — публичный HTTPS-URL dev-сервера.
- `CORS_ORIGINS` — включить origin dev-сервера.

## Тесты

Модульные тесты выполняются под vitest + jsdom:

```bash
bun run test:web
```

End-to-end браузерные тесты для компонента заметок (реальный Chromium, реальная
блокировка фокуса `inert`, реальные round-trip localStorage) лежат в корне репозитория
в `e2e/`:

```bash
bun run test:e2e          # headless
bun run test:e2e:ui       # Playwright UI mode (debug)
```

Спецификация управляет фикстурной страницей, отдаваемой Vite (`web/e2e-fixtures/scratchlist-fixture.html`),
которая монтирует продакшен-`ScratchlistPanel` изолированно, поэтому никакой настройки hub /
auth / socket не требуется.

## Сборка

```bash
bun run build:web
```

Собранные ассеты попадают в `web/dist` и отдаются hapi-hub. Единый исполняемый файл может встраивать эти ассеты.

## Самостоятельный хостинг

Можно разместить `web/dist` на статическом хосте (GitHub Pages, Cloudflare Pages) и направить на любой хаб hapi:

1. Соберите веб-приложение. Если ваш статический хост использует подпуть, задайте base Vite:

```bash
bun run build:web -- --base /<repo>/
```

2. Разверните `web/dist` на вашем статическом хосте.
3. Настройте CORS хаба, разрешив статический origin (`HAPI_PUBLIC_URL` или `CORS_ORIGINS`).
4. Откройте статический сайт, нажмите кнопку Hub в правом верхнем углу на экране входа и введите origin хаба hapi.

Очистите переопределение хаба в том же диалоге, чтобы вернуться к поведению с тем же origin.
