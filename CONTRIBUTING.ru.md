# Участие в HAPI

Спасибо за интерес к HAPI! Мы рады исправлениям багов, предложениям функций и вдумчивому вкладу сообщества.

## Кодекс поведения

- **Будьте дружелюбны и уважительны** — относитесь ко всем с добротой и профессионализмом
- **Помогайте другим** — делитесь знаниями и помогайте коллегам-участникам
- **Давайте конструктивную обратную связь** — сосредоточьтесь на коде, а не на человеке
- **Будьте терпеливы** — помните, что у всех разный уровень опыта

## Политика кода, сгенерированного ИИ (Vibe Coding)

Если вы использовали ИИ-инструменты для генерации кода («Vibe Coding»), укажите модель в описании PR. Код оценивается по существу — сфокусированный объём, тесты и прочие ожидания ниже применяются одинаково независимо от того, как код был создан.

## Правила Pull Request

### Никаких мега-PR

Мы не принимаем слишком большие pull request'ы, вводящие крупные функции разом. Большие PR:

- Трудно тщательно ревьюить
- Более склонны вносить баги
- Труднее откатывать при проблемах

**Если хотите добавить значительную функцию, сначала откройте issue для обсуждения подхода.** Мы поможем разбить её на меньшие, обозримые части.

### Лучшие практики PR

- Держите PR сфокусированным на одной теме
- Пишите ясные сообщения коммитов
- Включайте релевантные тесты, если применимо
- Обновляйте документацию при необходимости
- Ссылайтесь на связанные issue в описании PR

## Отчёты об ошибках

Отчёты об ошибках всегда приветствуются! При отчёте об ошибке укажите:

- Ясное описание проблемы
- Шаги воспроизведения
- Ожидаемое и фактическое поведение
- Ваше окружение (ОС, версия Node/Bun и т.д.)
- Любые релевантные логи или скриншоты

## Запросы функций

Есть идея улучшить HAPI? Откройте issue с:

- Ясным описанием функции
- Проблемой, которую она решает
- Любыми вашими идеями реализации

## Начало работы

1. Сделайте форк и клонируйте репозиторий
2. Установите Bun 1.4.0, затем установите зависимости из корня репозитория:
   ```bash
   bun install
   ```
3. Запустите разработку:
   ```bash
   bun run dev
   ```

Дополнительные варианты сборки см. в [README](README.md).

Из корня репозитория `bun typecheck` проверяет CLI, Hub, Web и Relay;
`bun run test` запускает Vitest CLI/Web и Bun-тесты Hub/Shared/Relay. Нативные
тулчейны и проверки описаны в [iOS](ios/README.md) и
[Android](android/README.md).

При изменениях документации запустите `bun run --cwd docs docs:build` и проверьте
затронутые ссылки и анкоры в сгенерированном сайте.
