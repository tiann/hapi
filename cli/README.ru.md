# hapi CLI

Выберите поддерживаемого агента кодинга в терминале и управляйте его сессиями удалённо через хаб hapi. См. [поддерживаемые агенты](../docs/guide/agents.md) (англ.).

## Что он делает

- Запускает сессии Claude Code и регистрирует их в hapi-hub.
- Запускает режим Codex для сессий на базе OpenAI.
- Запускает режим Cursor Agent для сессий Cursor CLI.
- Запускает Grok Build локально или через ACP для удалённых сессий.
- Запускает режим OpenCode через ACP и его систему хуков плагинов.
- Запускает DeepSeek Harness через внешний ACP stdio-сервер.
- Предоставляет MCP stdio-мост для внешних инструментов.
- Управляет фоновым раннером для долгоживущих сессий.
- Включает диагностику и помощники аутентификации.

## Типичный поток

1. Запустите хаб и задайте env-переменные (см. ../hub/README.ru.md).
2. Задайте тот же CLI_API_TOKEN на этой машине или выполните `hapi auth login`.
3. Запустите `hapi`, чтобы выбрать агента, или `hapi <agent>`, чтобы запустить его напрямую.
4. Наблюдайте и управляйте через веб-приложение или Telegram Mini App.

## Команды

### Команды сессий

- `hapi` — выбрать агента интерактивно. Недоступные агенты показаны с причиной и не могут быть выбраны.
- `hapi claude` — запустить сессию Claude Code (пробрасывает флаги Claude CLI).
- `hapi codex` — запустить режим Codex. См. `src/codex/runCodex.ts`.
- `hapi codex resume <native-thread-id>` — возобновить разговор Codex по его нативному thread ID. Для id сессии HAPI используйте `hapi resume <id>`.
- `hapi cursor` — запустить режим Cursor Agent. См. `src/cursor/runCursor.ts`.
  Поддерживает `hapi cursor resume <chatId>`, `hapi cursor --continue`, `--mode plan|ask`, `--yolo`, `--model`.
  Поддерживаются локальный и удалённый режимы; новые удалённые сессии используют `agent acp`. Сессии до ACP сохраняют устаревший путь resume `agent -p` stream-json.
- `hapi grok` — запустить режим Grok Build. См. `src/grok/runGrok.ts`.
- `hapi copilot` — запустить режим GitHub Copilot.
- `hapi kimi` — запустить режим Kimi.
- `hapi agy` — запустить режим Antigravity (только удалённо).
- `hapi pi` — запустить режим Pi (только удалённо).
- `hapi opencode` — запустить режим OpenCode через ACP. См. `src/opencode/runOpencode.ts`.
  Примечание: OpenCode поддерживает локальный и удалённый режимы; локальный режим транслируется через плагины OpenCode.
- `hapi dsh` — запустить DeepSeek Harness через ACP. См. `src/dsh/runDsh.ts`.
  DSH работает только удалённо, и его ACP-сервер нужно настроить отдельно.
- `hapi resume [sessionId]` — список возобновляемых сессий для этой машины или возобновление одной локально.
- `hapi ping-peer <session-id-prefix> <message>` — возобновить (если нужно) и отправить сообщение другой сессии. Предпочитайте это или MCP `ping_peer` / `list_peers` вместо изобретения JWT+curl. Также `--message-file` / `--list`.
- `hapi inspect-peer <session-id-or-prefix>` — метаданные пира только для чтения + текст последних сообщений (без возобновления). Предпочитайте это или MCP `inspect_peer`, когда пользователь ссылается на `[title](/sessions/<id>)` или ссылку Copy-reference `See session "…" (/sessions/<id>) for context`. `/sessions/<id>` — путь хаба, а не локальный файл. Необязательный `--limit`.

Список агентов в пикере отсортирован по алфавиту по имени команды. Используйте Up/Down и Enter
для выбора; Esc или Ctrl-C отменяет. Он появляется при каждом «голом» запуске, даже
когда доступен только один агент. Агент по умолчанию или выбор не сохраняется.

Скрипты и неинтерактивные оболочки обязаны указывать агента. Старые неявные команды Claude,
такие как `hapi --yolo`, `hapi --resume` и `hapi "prompt"`, теперь сообщают
об ошибке; используйте `hapi claude --yolo`, `hapi claude --resume` или
`hapi claude "prompt"` вместо них.

`hapi --help`, `hapi -h` и `hapi help` показывают только справку HAPI, не запуская
сессию и не требуя установленного агента. `hapi --version` / `hapi -v` показывают
версию HAPI. Флаги после имени агента обрабатываются существующей
интеграцией этого агента; поддерживаемые флаги различаются по агентам. HAPI не переводит и не добавляет
справочный текст агента.

### Возобновление удалённой сессии локально

```bash
hapi resume
hapi resume <session-id>
```

`hapi resume` перечисляет возобновляемые сессии для текущей машины. `hapi resume <session-id>` передаёт активную удалённую сессию и открывает ту же сессию HAPI в локальном терминале.

Для Codex терминал и веб остаются пригодными одновременно. Закрытие
исходного терминала останавливает запущенный из терминала прогон, но его история остаётся
возобновляемой. Сессии, запущенные из веба, работают под раннером; закрытие
подключённого позже терминала их не останавливает. **End session** архивирует
выбранный разговор. Подробности см. в [использовании и ограничениях Codex](../docs/guide/codex-shared-sessions.md) (англ.).

### Ответы на локальные промпты Claude из HAPI

В локальной сессии Claude, запущенной через `hapi claude`, вопросы `AskUserQuestion`
основной сессии и запросы разрешений инструментов также можно отвечать из веб-приложения.
Диалог терминала остаётся пригодным; ответ не перезапускает Claude и не переключает
сессию в удалённый режим. Claude арбитрирует гонки терминала/веба, а HAPI
записывает нативный результат, а не предполагает победу веб-ответа.

Мост использует хук Claude `PermissionRequest`, а не блокирующий
гейт одобрения `PreToolUse`. Неотвеченный удалённый запрос истекает через один
час; истечение, разрыв соединения или сбой моста оставляют нативный промпт
доступным. Локальные ответы/отмена, изменения сессии и переключения режима
отзывают устаревшие веб-элементы. Обнаружение отмены может ждать следующего
сканирования транскрипта.

Проверено на Claude Code **2.1.221**. Фоновые субагенты, `ExitPlanMode`
и запросы, которые нельзя однозначно сопоставить с нативным вызовом инструмента, остаются
только в терминале. Более ранние версии Claude не проверялись.

### Аутентификация

- `hapi auth status` — показать конфигурацию аутентификации и источник токена.
- `hapi auth login` — интерактивно ввести и сохранить CLI_API_TOKEN.
- `hapi auth logout` — очистить сохранённые учётные данные.

См. `src/commands/auth.ts`.

### Управление раннером

- `hapi runner start` — заменить существующий раннер и запустить отсоединённый процесс с переданными флагами/окружением.
- `hapi runner stop` — остановить раннер корректно; сессии агентов остаются живыми.
- `hapi runner start-sync` — работать на переднем плане (для супервизора процессов).
- `hapi runner status` — показать диагностику раннера.
- `hapi runner list` — список активных сессий под управлением раннера.
- `hapi runner stop-session <sessionId>` — завершить конкретную сессию.
- `hapi runner logs` — вывести путь к последнему файлу лога раннера.

И `start`, и `start-sync` принимают повторяемый `--workspace-root <path>` (или `--workspace-root=<path>`). Когда задан:

- Веб-страница `/browse` показывает ограниченные деревья файлов с корнем в этих путях.
- Раннер отклоняет запросы `list-directory` и `spawn-session` для путей вне настроенных корней.
- `~` и `~/foo` разворачиваются.

Пропуск флага оставляет ручной запуск сессий без ограничений и отключает
веб-функцию `/browse`. Поиск каталогов машины, используемый автодополнением сессий
и нативными пикерами, всё ещё доступен, но ограничен домашним каталогом
раннера.

См. `src/runner/run.ts`.

### Диагностика

- `hapi doctor` — показать полную диагностику (версия, статус раннера, логи, процессы).
- `hapi doctor clean` — убить сбежавшие процессы HAPI.

См. `src/ui/doctor.ts`.

### Прочее

- `hapi mcp` — запустить MCP stdio-мост. См. `src/codex/happyMcpStdioBridge.ts`.
- `hapi hub` — запустить встроенный хаб (workflow единого бинарника).
- `hapi server` — псевдоним `hapi hub`.

### MCP-серверы Codex

Сессии Codex сохраняют MCP-серверы, настроенные в `config.toml` Codex
пользователя. HAPI добавляет свой мост `hapi`, не заменяя другие пользовательские
серверы. Когда запуск через раннер передаёт токен аутентификации Codex, он копирует только
`config.toml` во временный `CODEX_HOME` и записывает переданный `auth.json`,
сохраняя настройки MCP без копирования постороннего состояния аутентификации.
Без переданного токена Codex использует обычный Codex home/auth раннера.
Имя сервера `hapi` зарезервировано HAPI.

В Windows известные шимы менеджеров пакетов (`uvx`, `npx`, `npm`, `pnpm`, `yarn`,
`bunx` и команды `.cmd`/`.bat`) используют короткоживущий stdio-прокси совместимости HAPI
перед обращением к настроенному MCP-серверу. Прокси хранит исходную
команду и аргументы в сессионном временном файле и пересылает байты MCP JSON-RPC,
не помещая значения env-переменных в аргументы или этот файл.
Секретные и сетевые переменные всё равно должны быть перечислены в `env_vars`
записи MCP (или переданы через `env`); HAPI не пересылает всё окружение
хоста автоматически.

## Конфигурация

Все параметры см. в `src/configuration.ts`.

DeepSeek Harness ACP по умолчанию использует `dsh-acp-demo`. Переопределите исполняемый файл или
его аргументы без разбора оболочкой:

```bash
export HAPI_DSH_ACP_COMMAND=dsh-acp-demo
export HAPI_DSH_ACP_CONFIG=/path/to/deepseek-harness/examples/acp-agent/cordis.yml
hapi dsh
```

Для выгрузки исходников используйте JSON-аргументы:

```bash
export HAPI_DSH_ACP_COMMAND=pnpm
export HAPI_DSH_ACP_ARGS_JSON='["--dir", "/path/to/deepseek-harness", "run", "demo:acp"]'
```

Официальное демо ACP работает только со свежими сессиями и не поддерживает нативный resume,
переключение моделей, инъекцию MCP или живую телеметрию инструментов/рассуждений. HAPI использует
стандартные поверхности чата и одноразовых разрешений; композиция ACP
владеет общей политикой разрешений, а HAPI не объявляет управление resume или
моделью для DSH.

### Обязательные

- `CLI_API_TOKEN` — общий секрет; должен совпадать с хабом. Можно задать через env или `~/.hapi/settings.json` (env побеждает).

### Необязательные

- `HAPI_API_URL` — базовый URL хаба (по умолчанию: http://localhost:3006; также настраивается как `apiUrl` в settings).
- `HAPI_HOME` — каталог конфигурации/данных (по умолчанию: ~/.hapi).
- `HAPI_EXPERIMENTAL` — включить экспериментальные функции (true/1/yes).
- `HAPI_EXTRA_HEADERS_JSON` — JSON-объект дополнительных заголовков для запросов CLI → хаб, например `{"Cookie":"CF_Authorization=..."}`. Также можно задать как объект `extraHeaders` в `~/.hapi/settings.json` (переменная окружения побеждает).
- `HAPI_CLAUDE_PATH` — путь к конкретному исполняемому файлу `claude`.
- `HAPI_DSH_ACP_COMMAND` — исполняемый файл ACP-сервера для `hapi dsh` (по умолчанию: `dsh-acp-demo`).
- `HAPI_DSH_ACP_CONFIG` — необязательный путь `dsh-acp-demo --config`.
- `HAPI_DSH_ACP_ARGS_JSON` — необязательный JSON-массив аргументов ACP-сервера.
- `HAPI_HTTP_MCP_URL` — цель MCP по умолчанию для `hapi mcp`.

### Раннер

- `HAPI_RUNNER_HEARTBEAT_INTERVAL` — интервал heartbeat в мс (по умолчанию: 60000).
- `HAPI_RUNNER_HTTP_TIMEOUT` — таймаут HTTP для управления раннером в мс (по умолчанию: 10000).
- `HAPI_RUNNER_WEBHOOK_TIMEOUT_MS` — таймаут webhook старта сессии в мс (по умолчанию: 15000); увеличьте для медленного запуска/возобновления агента.
- `HAPI_DISABLE_VERSION_HANDOFF` — установите `1`, чтобы отключить автоматическую замену раннера при изменении бинарника CLI.
- `HAPI_RUNNER_SUPERVISED` — установите `1` только когда супервизор перезапускает раннер после выхода; включает управляемый путь веб-кнопки Restart.

### Worktree (задаётся раннером)

- `HAPI_WORKTREE_BASE_PATH` — базовый путь репозитория.
- `HAPI_WORKTREE_BRANCH` — имя текущей ветки.
- `HAPI_WORKTREE_NAME` — имя worktree.
- `HAPI_WORKTREE_PATH` — полный путь worktree.
- `HAPI_WORKTREE_CREATED_AT` — метка времени создания (мс).

### Задаётся для обёрнутого агента

- `HAPI_SESSION_ID` — текущий id сессии HAPI, доступный внутри оболочек агента. Используйте его в скриптах, нацеленных на текущий разговор, без перечисления сессий.
- Явно настроенный `HAPI_API_URL` также доступен оболочкам агента. HAPI не копирует секреты `CLI_API_TOKEN` из settings в окружение агента; учётные данные, уже присутствующие в родительском окружении, всё равно могут наследоваться. PTY веб-терминала вычищают секреты хаба.

Для обнаружения пиров и обмена сообщениями используйте MCP-инструменты сессии `list_peers`,
`inspect_peer` и `ping_peer` либо соответствующие команды CLI.
На удалённом хосте раннера настройте совпадающие URL хаба и токен, чтобы shell-
команды попадали в тот же хаб (`hapi auth login` сохраняет токен).

Например, этот помощник для выгрузки исходников показывает изображение в текущей
сессии, когда MCP недоступен:

```bash
bun scripts/tooling/hapi-display-image.mjs /absolute/path/to/image.png "optional title"
```

## Инварианты жизненного цикла сессии

При изменении bootstrap агента, передачи или инфраструктуры общих сессий:

- Интеграции с поддержкой передачи используют режимы владения `local` (терминал) и `remote` (управление вебом). Codex вместо этого поддерживает параллельных клиентов без переключения владения; см. [общие сессии Codex](../docs/guide/codex-shared-sessions.md) (англ.).
- Обычные обёртки экспортируют `HAPI_SESSION_ID` после bootstrap. Общий Codex использует MCP-мост на корень и `shell_environment_policy.set.HAPI_SESSION_ID`; никогда не помещайте id одного корня в общее окружение app-server. Реализация: `src/codex/shared/root.ts`, `src/codex/shared/runtime.ts`.
- Gemini остаётся историческим проводным flavor, а не запускаемой интеграцией. Запускаемый набор см. в [руководстве по поддерживаемым агентам](../docs/guide/agents.md) (англ.).

## Хранилище

Данные хранятся в `~/.hapi/` (или `$HAPI_HOME`):

- `settings.json` — пользовательские настройки (machineId, token, флаг онбординга). См. `src/persistence.ts`.
- `runner.state.json` — состояние раннера (pid, порт, версия, heartbeat).
- `logs/` — файлы логов.

## Требования

- Установите и аутентифицируйте агента, которого хотите использовать. Claude CLI (`claude` в PATH) требуется только для `hapi claude`.
- Cursor Agent CLI установлен (`agent` в PATH) для `hapi cursor`. Установка: `curl https://cursor.com/install -fsS | bash` (macOS/Linux), `irm 'https://cursor.com/install?win32=true' | iex` (Windows).
- Grok Build CLI установлен (`grok` в PATH) для `hapi grok`. Аутентифицируйтесь через `grok login --device-auth` на headless-машинах раннера или задайте `XAI_API_KEY`.
- OpenCode CLI установлен (`opencode` в PATH).
- Bun 1.4.0 для сборки из исходников.

## Сборка из исходников

Из корня репозитория:

```bash
bun install
bun run build:cli                 # Type-check the CLI; no executable output
bun run --cwd cli build:exe       # Host-platform executable in cli/dist-exe/<target>/
```

Для единого бинарника, который также встраивает веб-приложение:

```bash
bun run build:single-exe
```

## Структура исходников

- `src/api/` — связь с хабом (Socket.IO + REST).
- `src/claude/` — интеграция Claude Code.
- `src/codex/` — интеграция режима Codex.
- `src/cursor/` — интеграция Cursor Agent.
- `src/grok/` — нативный TUI Grok Build + интеграция ACP.
- `src/agent/` — общая поддержка совместимых с ACP агентов.
- `src/opencode/` — интеграция ACP + хуков OpenCode.
- `src/runner/` — фоновая служба.
- `src/commands/` — обработчики команд CLI.
- `src/ui/` — пользовательский интерфейс и диагностика.
- `src/modules/` — реализации инструментов (ripgrep, difftastic, git).

## Релиз

Из корня репозитория `bun run release-all <version>` обновляет пакет CLI,
общую версию приложения, iOS `MARKETING_VERSION` (приложение и расширение уведомлений, все
конфигурации) и стандартный `versionName` Android перед сборкой и публикацией.
Используйте `--dry-run`, чтобы посмотреть без изменения файлов и публикации. Номера нативных сборок
(`CURRENT_PROJECT_VERSION` / `versionCode`) управляются отдельно;
переопределение Android `-PhapiVersionName` сохраняется.
