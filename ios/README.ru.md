# HAPI iOS

Нативный клиент SwiftUI/UIKit для HAPI, независимый от `web/` на уровне кода.
Он разделяет [протокол клиента](../docs/api/client-contract/index.md) (англ.) и
сгенерированные вебом золотые фикстуры в `shared/fixtures/`.

## Текущие возможности

Приложение предоставляет сессии/чат, одобрения и вопросы, новые сессии,
вложения, файлы/Git, заметки, стандартную диктовку, usage/storage,
настройки и зашифрованные уведомления APNs. Оно сопрягается с несколькими хабами и
держит один активным. Списки сессий поддерживают фильтрацию по машине, закрепление и архивацию;
отправка в неактивную сессию может возобновить её и перенести черновик/навигацию,
когда возвращённый id сессии меняется.

Управление моделью, разрешениями и совместной работой Codex следует агенту/возможностям сессии;
usage/storage требуют пространства имён владельца. У Rename, Delete и явного Reopen
есть обёртки API, но нет текущего UI iOS. Различия платформ, функции только для веба и повседневное
использование см. в [руководстве по нативным приложениям](../docs/guide/native-apps.md) (англ.).

## Требования

- Xcode 16 или новее с поддержкой Swift 6.
- Целевая версия развёртывания: iOS 17.0.
- Runtime-зависимости (SPM, объявлены в `Packages/HapiKit/Package.swift`,
  используются только целью `HapiUI`): `swiftlang/swift-markdown` (разбор GFM
  для собственного рендерера) и `raspu/Highlightr` (подсветка кода, спрятана
  за протоколом, поэтому заменяема). `HapiProtocol`/`HapiClient` остаются
  без зависимостей.

## Сборка

Архитектура прокрутки нативного чата и чек-лист приёмки:
[Прокрутка нативного транскрипта](../docs/native-chat-scrolling.md) (англ.).

Откройте `ios/Hapi.xcodeproj` в Xcode и запустите общую схему `Hapi`, либо из
командной строки:

```sh
# App (simulator, no signing)
xcodebuild build -project ios/Hapi.xcodeproj -scheme Hapi \
  -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO

# Package tests (macOS; protocol/client plus UI package tests)
swift test --package-path ios/Packages/HapiKit
```

CI запускает тесты пакета, сборку для симулятора и hosted-в-приложении тесты транскрипта
на `macos-15` через `.github/workflows/ios.yml` (триггер — изменения в
`ios/**` и `shared/fixtures/**`).

### Проверка на Linux (без Mac)

`ios/scripts/linux-test.sh` компилирует и тестирует не-UI цели
(HapiProtocol + HapiClient и их наборы тестов, включая золотые наборы
`shared/fixtures`) в Linux-контейнере Swift:

```sh
ios/scripts/linux-test.sh                # full swift test in docker
ios/scripts/linux-test.sh --filter Chat  # extra args pass through to swift test
```

Требуется docker; по умолчанию образ `swift:6.1-noble`
(`HAPI_SWIFT_IMAGE` переопределяет). Скрипт rsync-ит пакет и
фикстуры в staging-каталог глубины репозитория (`HAPI_LINUX_STAGE` переопределяет;
сохраняется между запусками, поэтому сборки инкрементальные) и монтирует его в `/work`,
так что разрешение фикстур относительно `#filePath` в тестах работает без изменений.
Всегда редактируйте реальные файлы рабочего дерева — каждый запуск пере-стейджит их.

HapiUI (SwiftUI + swift-markdown + Highlightr) не может собираться на Linux;
`Package.swift` убирает UI-продукт/цели и их зависимости
под `#if os(Linux)`, а скрипт не включает эти исходники в
staging-копию. Немногие Darwin-only API в HapiClient компилируются условно
(`#if canImport(Security)` для хранилища Keychain — Linux-тесты
используют `InMemoryCredentialStore` через шов `CredentialStoring`;
`#if canImport(CryptoKit)` для дайджестов файлов снимков с запасным FNV-1a;
`#if canImport(FoundationNetworking)` для типов URLSession и
транспорта SSE на делегате там, где `URLSession.bytes` недоступен).

### Фикстуры соответствия протокола

Запускайте тесты пакета из полной выгрузки репозитория. Пути тестов разрешают
`shared/fixtures/` относительно `#filePath`; копирование только пакета теряет этот
контекст. Linux-скрипт стейджит пакет и фикстуры на нужной глубине.

| Набор | Покрытие |
|---|---|
| `HapiProtocolTests` | Декодирование провода, каталоги режимов, версионированные патчи и проекции normalize → reduce → group по золотым фикстурам. |
| `HapiClientTests` | Фикстуры пагинации через контроллер окна сообщений, конвейер/взаимодействия чата, REST-запросы, аутентификация, восстановление SSE, хранилища и push. |
| `HapiUITests` / `HapiTests` | Логика рендерера и hosted-в-приложении раскладка, взаимодействие, переиспользование и поведение транскрипта на поддерживаемых тулчейнах Apple. |

Соответствие фикстурам фиксирует семантику протокола/состояния, а не идентичное веб/нативное
представление. При изменении входов или генерации фикстур запустите
`bun run gen:fixtures` в корне репозитория и включите сгенерированные изменения; никогда
не редактируйте фикстуры вручную. См. [руководство по фикстурам](../shared/fixtures/README.md) (англ.) и
[разработку UI](#разработка-ui) для целевых hosted-в-приложении проверок.

Регрессионные проверки каталога новой сессии: `ios/scripts/linux-test.sh --filter
'NewSession|RemoteDirectoryBrowser'` покрывает запросы путей и навигацию браузера;
`HapiTests/NewSessionDirectoryTests` покрывает значения по умолчанию формы, обновление ростера,
офлайн-машины и валидацию spawn. На устройстве проверьте home → родитель → проект
вне home, явные префиксы корней рабочего пространства, завершение `~/` и скрытых каталогов
и очистку ввода, пока приходят обновления здоровья машины. Восстановленная или выбранная
офлайн-машина остаётся выбранной, пока пользователь не выберет
онлайн-машину; её старый путь никогда молча не переносится на другой хост.

## Сопряжение

Приложение поддерживает несколько хабов с одним активным выбором. Правила провода см. в
[контракте auth](../docs/api/client-contract/auth.md) (англ.).

- **Ручной ввод:** запустите `hapi hub --relay`, затем *Enter Manually* → HTTPS-
  адрес хаба и токен доступа → *Pair*. Адрес начинается пустым, с отдельным меню
  протокола, по умолчанию HTTPS; введите домен/IP и необязательный
  порт без схемы. Вставка полного HTTP(S)-URL обновляет это меню. Полная
  ссылка сопряжения компаньона или веба, вставленная в любое поле, заполняет оба значения
  для проверки — соединение начинает только отправка формы. Для хаба из исходников
  `bun run dev` поставьте HTTPS-обратный прокси или туннель перед
  `localhost:3006`; физический телефон должен дотянуться до этого эндпоинта. Приложение проверяет `GET /health`,
  требует `protocolVersion == ProtocolVersion.supported`, обменивает
  токен через `POST /api/auth` и сохраняет учётные данные в Keychain.
- **Сканирование QR:** встроенный сканер принимает обе формы QR хаба —
  `hapicompanion://bind?hub=…&code=…` и URL прямого веб-доступа
  `https://<web>/?hub=…&token=…`. Веб **Настройки → Companion pairing** также
  показывает QR компаньона.
- **Диплинк:** открытие `hapicompanion://bind` показывает подтверждение сопряжения;
  уже сопряжённый хаб можно выбрать напрямую.
- **Симулятор:** используйте ручной ввод, потому что `DataScannerViewController`
  недоступен. Сопряжение камерой необязательно и на физических устройствах.
- **Выход:** home → меню хаба удаляет учётные данные этого хаба и откатывается
  к другому сопряжённому хабу или сопряжению. Отклонённый токен доступа или свежевыданный
  JWT, отклонённый снова, запускает повторное сопряжение. Временные сетевые/5xx сбои обновления
  сохраняют учётные данные.

Парсер принимает HTTP-URL. Ручной ввод использует выбранный протокол
(по умолчанию HTTPS); HTTP должен быть выбран явно или передан в полном URL
или ссылке сопряжения. Форма предупреждает, что HTTP не шифруется и может быть ограничен
iOS. Она никогда не угадывает HTTP для локального адреса и не понижает протокол после неудачного
HTTPS-подключения. Принятие ввода — не освобождение от требований транспорта.
`Hapi/Info.plist` и настройки сборки проекта не объявляют исключений ATS,
включая `NSAllowsLocalNetworking`. Используйте HTTPS-эндпоинты для надёжной
настройки сопряжения; поведение HTTP остаётся подчинено системной сетевой политике.

Ручная приёмка на уровне приложения: сопрячь → убить/перезапустить → фон/передний план →
сопрячь второй хаб и переключить → выйти → отсканировать обе формы QR → открыть диплинк
для несопряжённых/сопряжённых хабов. Также проверьте, что временные сбои хаба сохраняют
сопряжение, а отклонённый ротированный токен показывает баннер выхода.
Форма ручного ввода и системная вставка покрыты hosted-в-приложении
`ManualPairingFormTests` и `ManualEntryPresentationTests`; чистое поведение сопряжения
и auth покрыто тестами пакета; этот чек-лист — для
обвязки приложения и взаимодействия с платформой.

## Push-уведомления

Push APNs со сквозным шифрованием; детали провода — в
[контракте нативного push](../docs/api/native-companion-contract.md) (англ.). Официальные
сборки используют push-реле хаба по умолчанию. Самостоятельно подписанные сборки нуждаются в совпадающих
учётных данных провайдера, как описано ниже.

**Как это работает**

- **Регистрация.** После первого успешного сопряжения приложение запрашивает
  разрешение на уведомления (стандартный запрос alert/sound/badge — как в
  Android: никогда на чистой несопряжённой установке), регистрируется в APNs и
  отправляет `POST /api/devices/register`
  `{token: <hex APNs token>, platform: "ios", deviceId: <stable UUID>,
  pushKey: <base64 32-byte key>}` в **каждый** сопряжённый хаб — каждый хаб шлёт push
  независимо для своего пространства имён. Регистрация повторяется при каждом запуске приложения
  и ротации токена (дешёвый upsert; лечит переустановки и очистку на стороне
  хаба), а в Настройках → Уведомления есть ручное *Re-register push*.
  Выход отправляет best-effort `DELETE /api/devices/register {token}` из
  снимка учётных данных, взятого до стирания Keychain. Фоновой очереди повторов нет
  (у части WorkManager в Android нет iOS-эквивалента) — следующий триггер лечит временные сбои.
- **E2E-конверт.** Хаб никогда не отправляет открытый текст через APNs. Проводное
  уведомление — `{aps: {mutable-content: 1, alert: <generic>},
  hapi: {v: 1, e: <envelope>}}`, где `e` —
  `base64(nonce[12] || AES-256-GCM ciphertext || tag[16])` над JSON
  контракта данных FCM, с ключом `pushKey` этой установки и AAD
  `hapi-push-v1`. Доставляет ли хаб через прямой APNs или реле —
  целиком на стороне хаба — приложение только регистрируется и расшифровывает.
- **Notification Service Extension.** appex `HapiNotificationService`
  расшифровывает на устройстве: читает push-ключ из общей группы доступа
  Keychain (`$(AppIdentifierPrefix)run.hapi.companion.push`,
  after-first-unlock, чтобы push на экране блокировки расшифровывались), подставляет реальные
  заголовок/тело, проставляет категорию действия и сохраняет расшифрованные поля в
  `userInfo` для обработчиков нажатия/действий. Нерасшифровываемые payload доставляют
  общий алерт без изменений. appex не линкует ничего сверх SDK — он
  несёт SDK-only копию расшифровки `PushEnvelope` из HapiKit, честность которой
  поддерживается общим тестовым вектором.
- **Действия.** `permission-request` → Allow / Deny; `ready` и
  `task-notification` → встроенный Reply. `input-request` показывает первый
  вопрос, число оставшихся вопросов и имя сессии, только с открытием по нажатию
  (без одобрения или Reply). Apple Watch зеркалит превью; ответ — на
  телефоне. Обработчики выполняются в асинхронном completion делегата
  уведомлений и находят владеющий хаб в стиле Android
  (сначала активный хаб, затем ростер; 404 "Session not found" / 403 = попробовать
  следующий хаб) — approve/deny отправляют `{}`, reply отправляет `{text, localId}`.
  Сбои показываются локальным уведомлением, а не исчезают. Нажатие делает диплинк
  в чат сессии; push для чата, открытого на экране, подавляется
  (поток SSE в приложении уже показывает его).

**Карта слоёв**: `HapiClient/Push/` (конверт + payload + ключ, тестируется на Linux),
`Endpoints/DeviceEndpoints.swift` (register/unregister),
`Hapi/Models/PushCoordinator.swift` (регистратор + делегат + исполнитель действий),
`HapiNotificationService/` (appex). Расшифровка AES-GCM и контрактный
тестовый вектор проверяются `HapiClientTests/Push/*` — структурные проверки идут
в Linux-контейнере, тесты вектора/подмены CryptoKit — на Darwin CI.

### Самостоятельно подписанные сборки с push

1. Выберите платную/организационную команду в *Signing & Capabilities* для обоих
   приложения `Hapi` и расширения `HapiNotificationService`. Используйте bundle ID,
   зарегистрированные за этой командой. Бесплатные личные команды не могут подписывать push-entitlements.
2. Сохраните одну и ту же группу доступа Keychain в обеих целях:
   `$(AppIdentifierPrefix)run.hapi.companion.push`. Приложение также объявляет
   `aps-environment: development`; итоговый entitlement определяет подпись распространения. Расширение делит ключ через `keychain-access-groups`,
   а не через контейнер App Group.
3. Настройте хаб с `HAPI_IOS_PUSH=apns` и `APNS_KEY_P8_PATH`,
   `APNS_KEY_ID`, `APNS_TEAM_ID` и `APNS_BUNDLE_ID`, совпадающими с подписанным приложением.
   Задайте `APNS_ENV=sandbox` для токенов разработки или `production` для
   токенов распространения. Либо используйте самостоятельно размещённое push-реле с
   совпадающими настройками провайдера. Официальное реле не может отправлять в произвольное
   самостоятельно подписанное приложение. См. [конфигурацию транспорта](../docs/api/native-companion-contract.md#transports-self-host-direct-apns-vs-official-relay) (англ.).

Доступность APNs на симуляторе зависит от хоста/рантайма и настроек
подписи. Используйте `xcrun simctl push <simulator> <bundle-id> <payload.json>` для локальной
инъекции уведомлений, с `hapi.e`, зашифрованным push-ключом этой установки.
Это проверяет локальную обработку, а не доставку провайдером. Проверьте регистрацию,
доставку в фоне/на экране блокировки и действия на подписанном физическом устройстве.

## Структура

| Путь | Ответственность |
|---|---|
| `Hapi.xcodeproj/` | Приложение, расширение уведомлений и hosted-в-приложении тесты. Исходники приложения используют синхронизированные папки Xcode. |
| `Hapi/Models/` | `AppModel` сопряжения/навигации, активный `HubSession`, `ChatSession` на чат и `PushCoordinator`. |
| `Hapi/Features/` | Экраны SwiftUI и модели приложения для сопряжения, сессий, чата, новых сессий, файлов, заметок и настроек; хостинг транскрипта UIKit. |
| `Packages/HapiKit/Sources/HapiProtocol/` | Foundation-модели провода, каталоги, парсер сопряжения, версионированные патчи, сведение чата, логика окна сообщений и парсеры Git. |
| `Packages/HapiKit/Sources/HapiClient/` | Auth/REST/SSE, хранилища и снимки на диск, окна сообщений, взаимодействие чата, вложения, диктовка, push и тестируемая логика функций. |
| `Packages/HapiKit/Sources/HapiUI/` | Переиспользуемый Markdown, подсветка синтаксиса, отрисовка диффов, тема и типографика. |
| `HapiNotificationService/` | SDK-only расширение, расшифровывающее содержимое APNs общим ключом Keychain. |
| `Packages/HapiKit/Tests/`, `HapiTests/` | Проверки пакета и hosted-в-приложении. |

Приложение владеет навигацией, жизненным циклом и представлением экранов; HapiKit поставляет
протокол, транспорт, тестируемую логику функций и переиспользуемый UI. `HapiProtocol` и
`HapiClient` собираются без UI-зависимостей на Linux.

Активный хаб поддерживает глобальное соединение SSE; открытый чат добавляет
соединение на сессию. Обработка событий чата упорядочена через актор окна.
Сохраняйте учётные данные/черновики на хаб, водяные знаки версий, курсоры возобновления
и навигацию вытесняющей сессии при изменении этой обвязки. Транскрипт
использует `AnchoredTranscriptList` (`UICollectionView` с хостингом SwiftUI) и
готовит Markdown вне главного потока; см.
[прокрутку нативного транскрипта](../docs/native-chat-scrolling.md) (англ.).

## Рабочий процесс заметок

Лоток поля ввода переключает локальное для сессии назначение `chat` / `scratchlist`.
Режим заметок показывает один недавний черновик или только заголовок, пока ввод
в фокусе или используются размеры текста специальных возможностей, и явно помеченное
действие **Save draft**. Нажмите заголовок, чтобы открыть полный список, или × для возврата в
чат. Закрытие ящика сохраняет ввод; взятие черновика или принятие отправки из очереди
возвращает в режим чата. Очередь остаётся
отдельной, автоматически доставляемой поверхностью.

Текст и вложения откладываются одним снимком. Неудачные сохранения сохраняют ввод и
повторяют тот же id записи. Взятие сохранённого вложения создаёт заимствованную ссылку
хаба без возобновления сессии; явная отправка из чата стейджит его в
каталог загрузок активной/возобновлённой сессии. Действия очереди не потребляют
поле ввода и используют стабильный локальный id для версии сохранённой записи. Неудачное
удаление после принятия повторяет только удаление. Полный инвентарь использует один
стек навигации для чтения и транзакционного редактирования, с защитами от отмены
и идентичностями редактора, защищающими от поздних загрузок.

Строки инвентаря показывают две строки текста, число вложений, **Take draft** и
меню для постановки в очередь, редактирования, копирования и удаления. Потяните вниз для поиска
(включая имена файлов вложений); полные имена файлов и относительные метки времени есть
в представлении деталей. Меню + редактора предлагает фото и файлы. Пустые состояния
и обычная обвязка избегают пояснительных абзацев; сбои остаются встроенными со
своим действием восстановления, без дублирующего тоста.

Регрессионные наборы: пакет `ScratchlistComposerWorkflowTests`,
`ScratchlistAttachmentFlowTests`, `ScratchlistStoreTests` и
`ComposerAttachmentsTests`; hosted-в-приложении `ScratchlistScreenModelTests` и
`ScratchlistPresentationTests` (включая сохранение анкера транскрипта).
Набор представления прикрепляет рендеры light/dark, compact, специальных возможностей, инвентаря
и редактора. Вручную проверьте клавиатуру/VoiceOver, варианты конфликтов,
повтор фото/файла и отправку в неактивную сессию на подключённом устройстве.

## Разработка UI

### Каталог локализации

`Hapi/Resources/Localizable.xcstrings` управляется **вручную**, включая каждую
запись `"extractionState" : "manual"`. Держите `SWIFT_EMIT_LOC_STRINGS = NO` для
приложения/расширения в Debug и Release. Эта настройка отключает извлечение компилятором;
она **не** мешает редактору Xcode синхронизировать или сохранять каталог.
Неуказанное владение всё ещё может превращать записи в `stale` при синхронизации.

Используйте нативное форматирование каталога Xcode (порядок ключей, отступы, экранирование), а не
общий JSON-форматтер. После добавления или правки переводов запустите из корня репозитория:

```sh
python3 ios/scripts/localizations.py --check   # read-only ownership check; no Xcode needed
python3 ios/scripts/localizations.py --fix     # macOS/Xcode: mark manual, normalize native format
```

Нормализатор использует `xcstringstool` на временной копии, проверяет, что все ключи,
переводы, варианты множественного числа и комментарии выжили, и записывает только при необходимости.
Он никогда не удаляет реальные записи: просмотрите/удалите нежелательные авто-добавленные записи
перед `--fix`, а не делайте их молча постоянными. Храните динамические значения
и декоративный текст дословно в SwiftUI там, где они не являются ключами локализации.

CI проверяет ручное владение, тестирует идемпотентность нормализации и проверяет, что
сборка/тестирование не перезаписывает каталог. Форматирование делегируется
установленному Xcode, а не переписывается в Python; `--check`
не навязывает байтовое форматирование одной версии Xcode другой.

После миграции существующей выгрузки используйте **Product → Clean Build Folder**, если
Xcode всё ещё синхронизирует старые результаты извлечения, затем пересоберите/переоткройте и изучите
дифф. Не скрывайте файл через `.gitignore`, `skip-worktree` и не восстанавливайте его
безусловно: реальные правки переводов должны оставаться видимыми и закоммиченными.

### Навигация и изменение размера на iPad

iPad использует двухколоночный `NavigationSplitView`: сессии на боковой панели и
отдельный стек навигации деталей для чат → файлы/просмотрщик/страницы процессов. Боковая
панель запрашивает 280–360pt (идеально 320pt); система сворачивает ту же иерархию
представлений в компактных окнах. iPhone сохраняет свой единый `NavigationStack`.
Холодные старты и переключения хаба показывают **Select a session**, пока пользователь не выберет
одну; уведомления и новые сессии могут открыть ID до прихода его строки списка.
Выбор и вложенная навигация в памяти, не восстанавливаются между запусками.

`SessionNavigationState` владеет выбором, путём деталей и видимостью колонок;
ни геометрия окна, ни фильтры боковой панели не могут их очищать. Повторное открытие
выбранной сессии сохраняет её страницу файлов. Другая/вытесняющая сессия сбрасывает
весь стек деталей, но поздний вытесняющий callback не может заменить чат,
который пользователь с тех пор выбрал. Только явные события удаления или успешные операции
архивации очищают текущий выбор, никогда оптимистичное удаление/откат списка.

Идентичность деталей основана на хабе/сессии, поэтому изменение размера сохраняет существующий
чат, черновик, лоток вложений и анкер транскрипта. Нативные меню/шторки остаются
нативными; диалоги выхода из хаба и вложений привязаны к своим кнопкам.
Явный манифест сцены отключает дополнительные окна HAPI, **а не** Split
View/Stage Manager с другими приложениями. Не включайте генерацию манифеста сцены
(которая генерирует поддержку нескольких сцен) и не требуйте полный экран. Многооконность,
инспекторы третьей колонки, горячие клавиши и drag/drop не реализованы.

`SessionNavigationTests` покрывает политику навигации/удаления и собранный манифест
сцены. `SessionSplitPresentationTests` работает на реальном симуляторе iPad и
использует продакшен-оболочку/список split плюс реальный нон-сетевой образец чата:
выбор, программное компактное открытие, вложенный Back, фильтрацию, изменение размера,
якоря чтения, сохранение черновика/вложения и жизненный цикл поверхности/подписки.
CI держит набор iPhone и добавляет iPad Air 11-inch (M2). Запустите локально:

```sh
HAPI_TEST_DEVICE_TYPE=com.apple.CoreSimulator.SimDeviceType.iPad-Air-11-inch-M2 \
  ios/scripts/test-transcript.sh \
    -only-testing:HapiTests/SessionNavigationTests \
    -only-testing:HapiTests/SessionSplitPresentationTests
```

Необязательные образцы: задайте `TEST_RUNNER_HAPI_IPAD_CAPTURE` как **новый временный
каталог**; это синтетические тестовые разговоры, а не релизные скриншоты.
Перед релизом вручную проверьте портрет и ландшафт mini/11/13 дюймов,
изменение размера на треть/половину экрана и Stage Manager, докинг/плавающую клавиатуру и
переходы аппаратной клавиатуры, light/dark, китайский/английский, Dynamic Type и
VoiceOver. Проверьте шторки настроек/новой сессии/заметок/инспекции при
изменении размера, навигацию по уведомлениям и переподключение фон/передний план.

### Типографика чтения

`HapiUI` разделяет цветовые палитры (`HapiTheme`) и разрешённые метрики Dynamic Type
(`HapiTypography`). Установите `.hapiTypography()` в корне представления,
вне `AnchoredTranscriptList`; хостимые строки наследуют эти метрики. Не
масштабируйте разрешённые значения снова. Текст body/пользователя/поля ввода начинается с 16pt,
встроенный код с 15pt, код/диффы/терминал с 14pt, подписи с 12pt.
Body и код добавляют 3pt и 2pt масштабированного межстрочного интервала соответственно.

Транскрипт и поле ввода разделяют центрированную колонку чтения максимум 720pt
с боковыми полями минимум 16pt. Изменения шрифта, Bold Text, локали и эффективной ширины
инвалидируют измерения высоты, сохраняя анкер чтения.
Обычные потоковые обновления сохраняют неизменные hosting roots и измерения.

Сообщения пользователя остаются полностью развёрнутыми до 8 000 символов и 120 строк исходника,
даже когда занимают несколько экранов. Только более крупные payload сворачиваются до превью
не более 2 000 символов / 24 строк. Порог сворачивания отделён от
бюджета превью; оба ограничивают фактический текст, передаваемый в раскладку. **View full
message** открывает принадлежащий экрану просмотрщик с одной смонтированной частью 4 000 символов / 80 строк исходника,
навигацией previous/next и точным копированием полного содержимого.
Постраничный просмотр сохраняет Unicode и пробелы, не сканируя весь payload при
открытии. Просмотрщик переживает переиспользование ячеек и приостанавливает скрытую историю/следование за хвостом;
закрытие сохраняет позицию чтения. Сохранённые/отправленные сообщения никогда не усекаются.

Набор транскрипта UIKit покрывает изменения типографики, переиспользование, уменьшение
текста, ширины планшета/телефона и следование за хвостом. Необязательные детерминированные визуальные
образцы покрывают light/dark/OLED, смешанный китайский/английский, код, таблицы, диффы,
одобрения и фактическое поле ввода. Они используют нон-сетевой тестовый интерактор;
это **не** живые разговоры и не скриншоты App Store. Захватывайте в
новый временный каталог, никогда поверх релизной галереи:

```sh
TEST_RUNNER_HAPI_TYPOGRAPHY_CAPTURE=/tmp/hapi-typography-review \
  ios/scripts/test-transcript.sh -only-testing:HapiTests/TypographySnapshotTests
```

### Инспекция инструментов

Встроенные одобрения используют нейтральную карточку со спокойным статусом
pending/submitting/handled, ссылкой на полный ввод и адаптивными строками действий. `ChatActionButtonStyle`
владеет полной целью минимум 44pt (углы 10pt); не добавляйте системные отступы
обрамлённых кнопок или другую минимальную высоту метки. Одобрения, навигация по вопросам
и действия плана разделяют только этот стиль, но никогда свои семантики отправки.
Действия сообщений в очереди также сохраняют цели 44pt и складываются, когда колонка слишком
узка. Нативные алерты, шторки и элементы форм сохраняют системный стиль.

`PermissionActionPresentationTests` покрывает гейты flavor, геометрию действий, состояния busy
и already-handled, сбои, темы и крупный текст. Чтобы захватить изолированные,
нон-сетевые образцы одобрений, задайте `TEST_RUNNER_HAPI_APPROVAL_CAPTURE` как
новый временный каталог и запустите через `ios/scripts/test-transcript.sh`.

Предложения планов (`ExitPlanMode` / `exit_plan_mode`) — это читаемые документы, а не
сводки активности: их полный Markdown `input.plan` остаётся видимым в
разговоре, до любых элементов одобрения. Тот же рендерер используется в
инспекторе; null-вывод не показывает вводящий в заблуждение заполнитель "No output".
Предложения общего Codex показывают **Implement plan** и **Continue planning** только
когда `agentState.codexPlanProposalId` активной сессии совпадает с id вызова
инструмента. Реализация использует выделенный эндпоинт плана, а не одобрение разрешения;
continue локально скрывает меню действий этого предложения и фокусирует поле ввода,
сохраняя его черновик и режим плана без отправки сообщения. Документ плана
остаётся читаемым, а новое предложение получает свежее меню. Состояние ожидания/ошибки
переживает переиспользование строк. Отозванные, исторические и дочерние предложения остаются только для чтения
(выполняющаяся операция/ошибка всё ещё может отображаться).
Планы прогреваются в кеше Markdown чата и никогда не используют обычный
бюджет предпросмотра/постраничного просмотра вывода инструмента. Инспектор сохраняет сырые поля под Source.

Сводки инструментов открывают нативную большую шторку вместо раскрытия своего вывода
внутри разговора. Группы инструментов тоже остаются одной строкой сводки: нажатие одной
открывает нативный ленивый список в том же инспекторе. Вызовы остаются хронологическими, причём
каждое новое представление изначально позиционировано на последнем инструменте. Поток
никогда не прокручивает список; **Latest tool** явно возвращает к его концу. Детали пушатся
внутри той же шторки, сохраняя позицию списка при Back. Оба уровня держат
действие Close на панели и нативный свайп для закрытия. Инспектор разрешает стабильные
id групп/инструментов из живых данных; изменения только вывода не переконфигурируют неизменные
сводки групп в транскрипте. Заголовки групп приоритизируют общее число вызовов над
счётчиками категорий.
Сводки файлов/изображений показывают действие и basename; команды используют ограниченное превью.
Успех спокоен, а выполнение/ошибки остаются видимыми; каждая строка сохраняет цель 44pt.
Правки показывают записанный ввод, с отдельным действием **View current file**.
Sidechain задач/агентов открывает страницу процесса; одобрения и ответы на вопросы остаются в
разговоре/процессе, а не в инспекторе только для чтения.

Инспекторы вопросов показывают записанные выборы, пользовательские ответы и примечания с
Markdown-вопросами/вариантами. `request_user_input` также восстанавливает ответы из
исторических результатов; живые ответы разрешений имеют приоритет. Отвеченные карточки
избегают дублирования результатов, но сохраняют ошибки и полный ввод/результат/ответы
под **Source**. Отправка ответа остаётся в разговоре.

Синхронные вопросы используют выделенную встроенную карточку, а не оранжевый
футер одобрения. Показывается только один вопрос за раз: одиночные нажатия переходят
к следующему вопросу, а вопросы с множественным выбором и текстовые используют **Next
question**. **Previous question** сохраняет все выборы и примечания; последний шаг
всегда требует **Submit answer**. Метки Recommended — только отображаемые бейджи,
никогда не выборы по умолчанию или перезаписанные проводные значения. Поля другого ответа/примечания
раскрываются по требованию; текстовые вопросы и предзаполненные черновики показывают их сразу.
Вопросы выбора Codex с `isOther: true` также предлагают **None of the above**.
Выбор этого остаётся на текущем вопросе и фокусирует необязательные примечания; пустые
примечания допустимы. Его проводное значение остаётся `None of the above` на любом языке,
а записанные ответы/примечания появляются в сводках и деталях. Запросы без
`isOther` (включая формы Pi и MCP) сохраняют свои прежние варианты.
Всё состояние формы переживает переиспользование ячеек транскрипта для сохраняемого запроса.
Успешные записи сворачиваются в сводки ответов; отсутствующие записанные ответы
показываются как обработанные, а не выводятся из локальных черновиков. Обычные одобрения сохраняют свой футер одобрения.

Тесты вопросов включают чистые проверки навигации/построения ответов и hosted-в-приложении
образцы раскладки/переиспользования (фейковые данные; без живого агента или сохранённых учётных данных):

```sh
TEST_RUNNER_HAPI_QUESTION_CAPTURE=/tmp/hapi-question-review \
  ios/scripts/test-transcript.sh -only-testing:HapiTests/QuestionAnswerDraftTests \
    -only-testing:HapiTests/QuestionCardPresentationTests
```

Инспекция приостанавливает следование за хвостом транскрипта и постраничную загрузку скрытой истории, не
открывая другую подписку SSE. Закрытие возвращает к анкеру чтения;
открытие/закрытие внизу само по себе не показывает **Back to latest**. Кнопка
появляется, когда транскрипт достаточно далёк от низа (или живой хвост был
вытеснен), и явно возобновляет следование. Вытесненные записи остаются видимыми как
помеченные снимки только для чтения; отсутствующие группы сохраняют своё последнее членство,
не переключаясь на другую группу. Неполная история помечена и может быть
загружена из разговора после закрытия инспектора. Крупный текст загружается
частями по 20 000 символов и может быть скопирован полностью; крупные диффы используют постраничный исходник
вместо жадных строк.

Инспектор распознаёт вызовы команд/скриптов/патчей с пространствами имён. Чтение файлов использует
подсветку языка исходника; текст веба/агента использует Markdown (крупные документы
откатываются к постраничному исходнику). Обычные вложенные конверты результатов разворачиваются, причём
метаданные выхода/статуса команды остаются видимыми. **Source** раскрывает исходный
ввод/результат, включая поля, не показанные в предпросмотре; смешанные текстово-медийные
результаты остаются JSON вместо потери нетекстовых блоков.

Hosted-в-приложении набор покрывает выбор, живые обновления, нативное представление шторки,
списки на 2/42/240 вызовов, начальное позиционирование, навигацию деталей, передачи поверхностей,
постраничный просмотр Unicode и сохранение позиции чтения. Нативные свайп-жесты и
плавность анимации на релизном устройстве всё ещё требуют ручной приёмки. Образцы транскрипта
запускают реальный ChatModel/ChatTranscriptView с фейковым HTTP и замкнутым
loopback SSE; образцы шторок нон-сетевые. Оба используют детерминированные тестовые
записи, а не живые сессии или скриншоты App Store. Захватывайте в свежий каталог:

```sh
TEST_RUNNER_HAPI_TOOL_CAPTURE=/tmp/hapi-tool-review \
  ios/scripts/test-transcript.sh -only-testing:HapiTests/ToolInspectionPresentationTests \
    -only-testing:HapiTests/ToolTranscriptPresentationTests
```

### Фильтрация главной

Главная сохраняет фиксированный заголовок Sessions: переключение хаба на ведущем крае,
Filters и New Session на замыкающем. Нативное меню сейчас
предлагает одиночный выбор машины; только применённые фильтры добавляют строку сводки.
Фильтры временны на главную/хаб и никогда не выбирают машину новой сессии.
Варианты/счётчики берутся из всех сводок сессий, включая исторические машины;
онлайн-ростер поставляет только имена. Отсутствующие имена используют помеченный короткий ID.
Обновления числа сессий не переупорядочивают варианты и не сбрасывают позицию прокрутки списка.

Hosted-в-приложении тесты фильтров используют наблюдаемые хранилища в памяти (без сети или сопряжения).
Необязательные захваты раскладки — тестовые образцы, не живые или App Store скриншоты:

```sh
TEST_RUNNER_HAPI_HOME_CAPTURE=/tmp/hapi-home-review \
  ios/scripts/test-transcript.sh -only-testing:HapiTests/SessionListFilterTests \
    -only-testing:HapiTests/HomeFilterPresentationTests
```

## Заметки

- Схема URL `hapicompanion://` регистрируется через `Hapi/Info.plist`,
  вместе со строками использования камеры (сопряжение по QR + захват вложения) и микрофона
  (диктовка); всё остальное генерируется через
  `GENERATE_INFOPLIST_FILE` + настройки сборки `INFOPLIST_KEY_*`. Современный
  внепроцессный `PhotosPicker` **не** требует разрешения на фотобиблиотеку, поэтому
  `NSPhotoLibraryUsageDescription` нет.
- `run.hapi.app` — bundle id; подпись `Automatic`, а CI собирает
  с `CODE_SIGNING_ALLOWED=NO`.
- CI использует Xcode по умолчанию раннера; каждая задача сначала печатает `xcodebuild -version`,
  чтобы сбои можно было отнести к обновлению тулчейна.
